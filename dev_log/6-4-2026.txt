2026-06-04  New game: WealthQuest (Flutter mobile finance sim)
  WHAT: Scaffolded a brand-new, standalone Flutter game under
        wealthquest/ on branch claude/new-mobile-game-repo-JDskF.
        It's unrelated to v1 (territory) and v2 (swarm) — a
        personal-finance / stock-market life sim. Core loop:
        start at age 18 with a day job; press "Next Day" to
        advance one in-game WEEK; salary lands, living expenses
        come out, every market moves (random walk), interest +
        bond coupons accrue, CDs mature, you age up every 52
        days. Data-driven catalog of 17 instruments across 5
        categories (savings, CDs, bonds, stocks, ETFs, crypto)
        — adding one is a single AssetDef entry. Four tabs:
        Dashboard (net-worth sparkline + cash-flow + activity
        feed), Market (buy), Portfolio (sell/redeem + live P/L),
        Life (age-gated career ladder). Pure, seedable market
        engine with unit tests (test/game_controller_test.dart).
  WHY:  User: "I want to create a new game/ repo. It is a mobile
        app... a stock market simulator. At the end of the day
        you say next day and see how your assets perform. CDs,
        bonds, all types of investments in categories. Start
        small, passive income from a day job at 18, every 'day'
        is a week." Picked: separate repo, Flutter, private.

  Notes:
   - Intended target was a STANDALONE GitHub repo
     (Armandoxh/wealthquest, private). The session's GitHub
     integration is scoped to armandoxh/territorygame, so
     create_repository returned 403. Built it here in
     wealthquest/ instead; README documents the git subtree
     split to relocate it to its own repo later.
   - Flutter not installed in the sandbox, so this ships
     lib/ + pubspec + tests only. Run `flutter create .` to
     generate android/ios/web around the existing lib/.
   - Followed the repo's incremental mantra: nailed ONE core
     loop, kept tunables in data/catalog.dart, engine branches
     on AssetKind (not specific assets) so new instruments are
     data not code. Deferred scope listed in the README.

2026-06-04  WealthQuest nail: rumor-mill newspaper
  WHAT: Added "The Daily Ledger" — a News tab that publishes a
        weekly edition of 2-3 rumors, each a bullish/bearish tip
        on one asset. Rumors mechanically bias next week's price
        move, but the mill is only ~25% reliable (base): a true
        rumor (25%) moves the asset its predicted way; a false one
        sometimes swings the other way, sometimes fizzles. Each
        week resolves last edition's tips (TRUE/FALSE stamp +
        actual move) and publishes a fresh one. Rumors also surface
        on each asset's detail screen ("Word on the street"). Built
        for the future upgrade tree: reliability is a field and a
        `reliabilityRevealed` flag gates showing the exact %, which
        stays hidden for now per the user's spec.
  WHY:  User: "a newspaper rumor mill — news that's most likely
        true but may swing the other way, right ~25% of the time.
        When we get the upgrade tree I want the user to see the %
        probability that news is right." Nail 2 of 2.

  Architecture:
   - models/rumor.dart, engine/news_engine.dart (headline
     templates per asset kind + generator, deterministic under
     seed). MarketEngine.stepPrice gained an optional `bias`.
   - GameController: currentRumors / lastResolved / rumorArchive +
     resolution-and-bias step in advanceDay, fresh edition each
     week. ui/news_tab.dart + News bottom-nav slot + rumor card on
     the asset detail screen.

2026-06-04  WealthQuest (build 9): market climate + crashes (insurance teeth)
  WHAT: Added a macro layer that makes 'uninsured' finally matter (fixes
        the MMF-dominates problem). models/climate.dart (MarketRegime:
        boom/normal/downturn/crash/recovery + SectorEvent) and
        engine/climate_engine.dart (Markov regime transitions, per-asset
        beta, sector boom/bust generator). Each week the regime rolls and
        applies a market-wide drift scaled by each asset's beta (bonds
        barely move, crypto swings hard); a CRASH applies a severe drop
        AND carves 2% off uninsured cash (MMF, CMA) while FDIC/govt
        options are untouched. Occasional sector events ('Tech rally',
        'Energy slump') bias one sector for 1-3 weeks. A climate banner
        on the News tab shows the current regime + active sector event;
        regime changes/crashes/sector events surface in the Next Week
        summary. Marked CDs insured so crashes don't hit them.
  WHY:  User: 'why would a player not just take the 4.8% MMF and ignore
        the rest?' Right — uninsured had no teeth. Now the yield premium
        of uninsured cash is a real risk premium paid back in crashes,
        and insured cash is a genuine safe harbor.
  TUNING: crash ~0.8%/wk from calm, ~5% from a bear; crashCashLoss 2%;
        beta = vol/0.03 capped at 2.0. Knobs in climate.dart /
        climate_engine.dart.
